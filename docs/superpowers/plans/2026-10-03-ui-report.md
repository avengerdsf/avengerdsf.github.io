- Homepage now contains a brief identity and research direction, four existing projects, and two real knowledge directory links. Existing project destinations and personal details remain. - At 900px and below the tree is a bounded overlay drawer with close button, backdrop, Escape handling, article selection close, focus return, Tab containment, inert background and scroll lock. Breakpoint changes clear mobile locks and overlays and retain the desktop collapse preference.
- More menu retains knowledge root/parent navigation, source-aware edit links and new-note action. Synthetic source indexes correctly omit edit actions when sourceFor returns null. API signatures are unchanged.
- Directory titles now retain full authored metadata instead of stripping “笔记”. Each overview continues listing only immediate child directories and notes. Authored Markdown was not modified.
- Existing theme bridge still shares homepage and Quartz theme storage. Native theme button receives a current Chinese accessible label.

## Integration fixes and actual browser evidence

The first built preview exposed two interaction defects. Both have targeted regressions run against a fresh real Chrome context.

1. Native explorer calls active.scrollIntoView after asynchronously rendering its tree. Restoring only the original ul overflow did not stop the page movement, because default scrollIntoView also scrolls the document when the selected item is already visible. A fresh 1024px article moved to scrollY 165, with title top -36px. The left desktop tree is now a fixed, independently scrolling region aligned to the existing grid start; native tree positioning cannot scroll its document ancestor. The mobile drawer retains its existing fixed positioning.
2. With a narrow directory modal open, Quartz Ctrl/Cmd+K previously made search visible while the center remained inert, so the search input could not receive focus. The bridge now clears the drawer in capture phase before the native shortcut handler runs. It leaves the shortcut and search focus behavior to Quartz. The search button also clears a directory modal before its native click handler.

## Final mobile drawer geometry fix

The independent audit found a 390x844px drawer with heading bottom 131px and explorer top 532.61px. Actual DOM contained a `mobile-only` wrapper with the old Quartz spacer. Its display:contents made the inner flex-growing spacer participate directly in the drawer despite the old direct-child hide selector.

Only the spacer plugin's enabled flag was changed to false. The new fixed drawer does not need that former layout helper; no CSS workaround or authored-content change was added. The concurrently added note-title plugin remains enabled at order 46.

The same real Chrome geometry regression first failed on the old preview and passed on the rebuilt preview: heading bottom 131px, explorer top 139px, gap 8px. The drawer now contains only its heading and the native explorer. Root is adding the `explorerTop <= headingBottom + 32` assertion to the main CI browser script.
