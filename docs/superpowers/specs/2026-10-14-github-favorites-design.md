# GitHub 私有仓库收藏同步

## 使用目标

在力扣笔记中收藏和取消收藏题目，支持从乱序浏览过程中操作。电脑和手机授权后读取同一份 GitHub 收藏记录。力扣目录页提供收藏夹，按最近收藏顺序展示题目名称。

收藏记录使用独立的私有 GitHub 仓库。浏览器中的授权状态与收藏数据分开保存。

## 界面

- 每篇力扣题目标题下提供“收藏”和“已收藏”按钮。点击已收藏按钮取消收藏。
- 乱序浏览时，收藏按钮与进度、返回列表和下一题按钮共同显示。收藏操作保持当前题目及乱序顺序。
- 力扣目录页增加“收藏夹”入口，使用现有题目卡片样式，支持进入题目复习。
- 未授权时，收藏操作或打开收藏夹会显示 GitHub 授权窗口。
- 授权窗口使用密码输入框填写访问令牌，提供“记住此设备”选项，默认关闭。未勾选时，授权仅保留在当前标签页；勾选后在本设备保留授权，退出授权时清除。
- 保存过程中按钮显示处理中状态。只有 GitHub 写入成功后才确认收藏状态；失败时显示重试提示。
- 收藏夹为空、读取失败和未授权分别显示对应状态。

## 存储与权限

目标仓库为 `avengerdsf/knowledge-favorites`，可复用同名的已有私有仓库；不存在时创建私有仓库。默认分支 `main`，收藏文件为 `favorites.json`。

初始文件：

```json
{
  "version": 1,
  "favorites": []
}
```

`favorites` 保存题目 slug，最新收藏放在数组开头。标题和链接使用当前知识库生成的元数据。已删除题目在收藏夹中不显示，收藏文件中的记录保留。

访问令牌仅授予收藏仓库的 Contents 读写权限。令牌通过 HTTPS 请求头传给 GitHub，不进入收藏文件、公开仓库或日志。收藏数据更新发生在独立仓库，不触发知识库网站发布。

GitHub Contents API 支持文件读取和写入，更新时需要现有文件的 SHA。[官方接口说明](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents)

## 同步规则

授权后、进入收藏夹或重新回到浏览器窗口时，读取 GitHub 中的最新记录。

收藏和取消收藏采用明确的添加或删除操作。每次写入前读取最新文件并合并本次操作，保留其他设备已保存的收藏。写入发生冲突时重新读取并重试一次；重试仍失败时提示用户，不覆盖未知状态。

重复添加和重复删除不产生重复记录。收藏文件内容或版本异常时停止写入并显示错误，避免覆盖已有数据。

## 代码组织

- 现有 `site-ui` 插件增加 GitHub 收藏读写模块和浏览器交互。
- 复用现有题目元数据、目录卡片和乱序会话。收藏操作不改变乱序顺序。
- UI 保持现有手机、桌面和 4K 布局，操作按钮可换行。
- 收藏以 LeetCode 题目为范围，章节索引、概述和其他知识分类不提供题目收藏按钮。

## 代码折叠修复

“合并两个有序链表”的代码区标题应为“代码”，保留算法代码和题面。代码区默认收起，点击可展开、再点击可收起。检查其余题解的主代码区折叠状态。

## 验证

1. 单元测试覆盖数据解析、添加和删除、顺序保留、授权失败、冲突重试及令牌隔离。
2. 浏览器测试验证乱序中收藏、继续下一题、取消收藏、收藏夹展示、刷新和独立浏览器上下文共享记录。
3. 核对私有仓库和初始文件，并检查实际 GitHub 读写配置。
4. 验证代码默认收起及展开、收起操作，检查其他主代码区。
5. 运行项目测试、源文件和构建验证，检查手机、桌面及 4K 窗口。

## 完成标准

收藏成功后记录存在 GitHub 私有仓库，另一设备授权后能够读取；取消收藏同样同步。收藏操作保留本轮乱序，网站正常显示收藏夹。代码折叠问题修复，仓库和网页中不包含访问令牌。
