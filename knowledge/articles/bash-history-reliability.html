Bash 历史记录可靠性

多个终端同时工作时，默认 Bash history 很容易出现“这条命令明明执行过却找不到”的体验。核心问题通常不是 history 坏了，而是写入时机和过滤规则。

BashHistoryUbuntuShell

1. 先看当前配置

echo "$HISTCONTROL"
echo "$HISTIGNORE"
echo "$HISTSIZE"
echo "$HISTFILESIZE"
echo "$HISTFILE"
shopt histappend

如果 HISTCONTROL=ignoreboth，Bash 会同时忽略“与上一条重复的命令”和“以空格开头的命令”。这经常就是某些记录消失的原因。

2. 确保不同终端追加，而不是互相覆盖

# ~/.bashrc
shopt -s histappend
HISTSIZE=10000
HISTFILESIZE=20000

histappend 会让 shell 退出时向历史文件追加内容，而不是直接覆盖整个文件。对于长期并行使用多个终端，这是基础配置。

3. 每次提示符出现时同步历史

# 每执行完一条命令就追加到 HISTFILE，并读取其他终端新写入的内容
PROMPT_COMMAND="history -a; history -n${PROMPT_COMMAND:+; $PROMPT_COMMAND}"

history -a 把当前会话新增命令立即写入历史文件；history -n 再读取其他会话新增的行。这样即使某个终端异常退出，已经执行过的命令也更不容易丢失。

注意：

如果现有 PROMPT_COMMAND 已经包含环境管理器、终端集成或其他逻辑，不要直接覆盖。应先检查原值，再把 history 同步逻辑安全地合并进去。

4. 决定你到底想忽略什么

# 仅忽略连续重复命令
HISTCONTROL=ignoredups

# 完整记录，包括重复和以空格开头的命令
HISTCONTROL=

如果目标是“尽可能完整地审计自己的命令”，不要使用 ignorespace / ignoreboth。如果只是减少噪声，ignoredups 通常更平衡。

5. 给历史命令增加时间戳

# ~/.bashrc
HISTTIMEFORMAT='%F %T '

# 重新加载
source ~/.bashrc

# 查看
history | tail -n 30

%F 是日期，%T 是时分秒。Bash 实际保存的是 epoch 时间，显示格式由 HISTTIMEFORMAT 控制。

6. 一个偏“可靠记录”的基础配置

# ~/.bashrc
shopt -s histappend
HISTCONTROL=ignoredups
HISTSIZE=10000
HISTFILESIZE=20000
HISTTIMEFORMAT='%F %T '
PROMPT_COMMAND="history -a; history -n${PROMPT_COMMAND:+; $PROMPT_COMMAND}"
验证
  • 开两个终端，在 A 执行一条唯一命令。
  • 回到 B 再按一次 Enter 触发新提示符。
  • 在 B 中执行 history | tail，确认能看到 A 的命令。
  • 关闭并重新打开终端，确认记录仍存在且带时间。
