## 题目

**题目链接：** [LeetCode 230 · 二叉搜索树中第 K 小的元素](https://leetcode.cn/problems/kth-smallest-element-in-a-bst/description/?envType=study-plan-v2&envId=top-100-liked)

给定一棵二叉搜索树的根节点 `root` 和整数 `k`，返回树中第 `k` 小的节点值。排名从 `1` 开始，`k = 1` 表示最小值。

输入已经保证是二叉搜索树，不需要像第 98 题一样先验证；返回的是**节点值**，不是节点对象或下标。

**示例 1**

```text
输入：root = [3,1,4,null,2], k = 1
输出：1

    3
   / \
  1   4
   \
    2
```

节点值从小到大是 `1、2、3、4`，第 `1` 小的值为 `1`。

**示例 2**

```text
输入：root = [5,3,6,2,4,null,null,1], k = 3
输出：3

      5
     / \
    3   6
   / \
  2   4
 /
1
```

节点值从小到大是 `1、2、3、4、5、6`，第 `3` 小的值为 `3`。两个示例及以下数据范围可在原题链接中核对。

**数据范围**

```text
1 <= k <= 节点数量 <= 10000
0 <= Node.val <= 10000
```

**进阶：** 树中经常插入、删除节点，同时需要频繁查询第 `k` 小的元素时，如何优化？

**ACM 输入输出**

你的完整程序第一行读取 `n k`，第二行读取空格分隔的层序数据，不带方括号和逗号。例如，示例 2 对应：

```text
输入：
8 3
5 3 6 2 4 null null 1

输出：
3
```

**这里的 `n` 是层序输入的标记数量，包含 `null`，不是实际节点数。** 代码使用 `data[2:2 + n]` 读取这些标记；上面的输入有 `8` 个标记、`6` 个实际节点，所以第一行是 `8 3`，不是 `6 3`。原题数据范围中的节点数量不包含 `null`。

## 解答

**核心思路：二叉搜索树的中序遍历是升序序列，按照“左子树 → 当前节点 → 右子树”的顺序计数，第 `k` 个就是答案。**

二叉搜索树中，左子树的所有值小于当前节点，右子树的所有值大于当前节点。先依次处理左子树，再处理当前节点，最后依次处理右子树，并在每棵子树中重复这一顺序，就能从小到大访问所有节点，不需要额外排序。

### 关键代码

保留你的 `Solution` 核心代码、变量名和递归顺序，不增加提前退出。`TreeNode` 使用 LeetCode 提供的定义；输入读取、层序建树和结果打印属于 ACM 辅助代码。

```python
class Solution:
    def __init__(self):
        self.min_k = None
        self.k = None

    def kthSmallest(self, root, k):
        self.k = k
        self.dfs(root)
        return self.min_k

    def dfs(self, node):
        if not node:
            return

        self.dfs(node.left)
        self.k -= 1
        if self.k == 0:
            self.min_k = node.val

        self.dfs(node.right)
```

`self.k` 是所有递归调用共用的剩余计数，`self.min_k` 保存答案。先完成 `self.dfs(node.left)`，再执行 `self.k -= 1`，表示轮到当前节点；减到 `0` 时，将 `node.val` 保存到 `self.min_k`。`dfs` 不直接返回答案，遍历结束后由 `kthSmallest` 返回 `self.min_k`。

### 中序遍历的过程

以示例 2 的 `k = 3` 为例，先设置 `self.k = 3`，从根节点 `5` 开始向左递归：`5 → 3 → 2 → 1`。**进入 `dfs` 不代表已经计数，必须等当前节点的左子树处理完。**

节点 `1` 的左孩子为空，这次空节点调用返回后，继续执行节点 `1` 的 `self.k -= 1`，计数从 `3` 变成 `2`。再检查它的右孩子，也是空节点，随后节点 `1` 的调用结束，回到节点 `2`。

节点 `2` 的左子树已经完成，计数从 `2` 变成 `1`。它的右孩子为空，处理后返回节点 `3`。此时节点 `3` 的左子树也已完成，计数从 `1` 变成 `0`，执行 `self.min_k = node.val`，保存答案 `3`。

代码没有提前退出，仍会处理节点 `3` 的右子树 `4`，随后回到根节点 `5`，再处理它的右子树 `6`。完整计数过程如下：

```text
当前节点    self.k 的变化    self.min_k
   1           3 → 2           None
   2           2 → 1           None
   3           1 → 0              3
   4           0 → -1             3
   5          -1 → -2             3
   6          -2 → -3             3
```

后续的 `self.k` 只会继续减小，不会再次等于 `0`，所以答案不会被覆盖。全部递归结束后，`kthSmallest` 返回 `3`。

### 易错点与复杂度

`self.k -= 1` 必须放在左子树递归之后、右子树递归之前。若放在左递归前，就会按“根 → 左 → 右”计数，不能保证第 `k` 个是第 `k` 小的值。题目中的层序输入只是用来建树，不能直接取输入数组的第 `k` 项。

`self.k == 0` 只负责记录答案，**并不终止递归**。这份代码会遍历整棵树，时间复杂度为 `O(n)`，这里的 `n` 指实际节点数，不能因为 `k` 很小就写成 `O(k)`。

递归栈的额外空间为 `O(h)`，`h` 是树高。平衡时为 `O(log n)`，退化为链时为 `O(n)`。本地运行很深的链状树时可能触及 Python 的递归深度限制，参见 [Python 官方说明](https://docs.python.org/3/library/sys.html#sys.getrecursionlimit)。
